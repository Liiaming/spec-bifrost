# Roadmap

[中文](#中文) / [English](#english)

## 中文

Spec Bifrost 当前目标是先成为一个可信、好试用、容易参与的开源项目，然后再评估商业化路径。

### 现在：Adoption 基础

- 优化 README 首屏叙事，让新用户快速理解价值、用法和边界。
- 保持采购申请管理系统示例可运行、可预览、可导出。
- 补齐 demo 截图、流程图、贡献指南、issue templates 和发布检查。
- 继续打磨 Claude Code 和 Codex 的安装与 skill 触发体验。

### 下一步：需求质量

- 收敛导出文档质量规则，包括 notes 合并、字段缺失、前后端内容裁剪。
- 丰富诊断文案，让 AI 和人都能更快定位 JSON 问题。
- 改进 preview 的空状态、条件规则展示和错误提示。
- 保持产品边界：输出需求原型和需求文档，不生成生产代码。

### 之后：生态与商业化

- 建立更多业务场景模板，但优先扩展示例质量，不盲目堆数量。
- 探索 GitHub Sponsors、Open Collective 或企业支持入口。
- 评估团队协作、托管预览、模板市场和定制咨询是否值得单独商业化。
- 商业化能力应围绕服务和协作，不应突然移走开源核心能力。

## English

Spec Bifrost is currently focused on becoming a trustworthy, easy-to-try, and contributor-friendly open source project before choosing a monetization path.

### Now: Adoption foundation

- Improve the README first screen so new users quickly understand the value, workflow, and boundaries.
- Keep the procurement request management example runnable, previewable, and exportable.
- Add demo screenshots, workflow diagrams, contribution docs, issue templates, and release checks.
- Keep improving Claude Code and Codex installation and skill-triggering experience.

### Next: Requirement quality

- Refine export quality rules, including notes merging, missing field handling, and frontend/backend content trimming.
- Improve diagnostics so both AI agents and people can locate JSON issues faster.
- Improve preview empty states, condition visibility, and error messaging.
- Preserve the product boundary: output requirement prototypes and requirement documents, not production code.

### Later: Ecosystem and commercialization

- Build more business scenario templates, while prioritizing example quality over raw quantity.
- Explore GitHub Sponsors, Open Collective, or enterprise support.
- Evaluate whether team collaboration, hosted previews, template marketplaces, or custom consulting deserve a commercial layer.
- Commercial work should focus on services and collaboration, not suddenly removing existing open source core capabilities.
