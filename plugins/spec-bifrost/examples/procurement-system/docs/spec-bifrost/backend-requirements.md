# 采购申请管理系统 后端需求说明

## 文档边界

本文档基于 `spec-bifrost.json` 导出，面向后端和业务规则沟通。内容只描述业务对象、字段口径、规则、流程结果和例外备注，不要包含接口定义、数据库设计、技术架构、代码结构或任务拆分。

用户原始场景中的“申请单列表”“创建申请”“审批详情”分别对应本示例中的采购申请列表、新建采购申请和采购申请详情。

## 业务对象与字段口径

### 采购申请

- 采购申请用于记录申请人发起的采购需求。
- 采购申请在用户界面中也可称为申请单。
- 申请编号用于唯一识别一条申请。
- 申请标题用于概括采购需求。
- 采购类型区分办公用品、软件服务和固定资产。
- 申请金额用于判断审批路径和补充说明要求。
- 审批状态包含草稿、审批中、已通过和已驳回，口径以审批流程当前节点为准。
- 列表概览指标用于表达审批中、大额申请和待补附件的业务统计口径。

### 采购明细

- 采购明细用于表达一条申请中包含的具体采购项。
- 明细项口径包括物品名称、数量、单价、预算科目和候选供应商。
- 可编辑明细行用于表达提交前可增补采购项，但提交后申请人不能直接修改明细。
- 采购明细数量至少为 1。
- 物品名称、品类标签、数量和单价用于帮助审批人与采购专员理解采购内容。

### 供应商参考

- 供应商等级包含优选供应商、合格供应商和临时供应商。
- 采购品类包含办公用品、软件服务和固定资产，并可进一步区分显示器、键盘鼠标、SaaS 订阅、开发工具授权、办公设备和研发设备等层级。
- 优选供应商可优先用于常规办公用品和低风险软件服务采购。
- 合格供应商可用于标准采购场景，大额采购需补充比价说明。
- 临时供应商仅用于特殊或一次性采购，审批人需要重点确认原因。

### 治理与协作事实

- 权限矩阵定义申请人、审批人和采购专员在创建申请、审批和批量导出上的权限口径。
- 规则清单包含大额审批、附件必传和批量导出的业务规则。
- 审计日志用于表达提交审批、审批通过和要求补充报价单等操作记录留痕。
- 评论串和审批意见用于保留部门负责人、财务审批等角色的业务意见。
- 关系图和关联单据用于表达采购申请、预算科目、供应商、合同和验收单之间的业务关系。

## 业务规则

- 申请金额必须大于 0。
- 期望到货日期不能早于提交日期。
- 软件服务采购需要上传报价单。
- 固定资产采购金额超过 10000 时，需要上传预算说明附件。
- 申请金额超过 50000 时，预算说明为审批关注点，且提交后进入大额审批路径。
- 申请金额小于等于 50000 时，提交后进入普通审批路径。
- 审批结论为驳回时，驳回原因必填。
- 驳回确认需要再次确认原因，用于申请人修改后重新提交。
- 批量导出作用于勾选的采购申请，不代表单条申请状态变化。
- 提交后申请人不能修改明细，只能撤回后重新编辑。
- 权限矩阵中的批量导出权限必须遵守当前角色可查看范围。
- 业务规则要求软件服务采购上传报价单，大额采购补充预算说明。

## 流程结果

- 保存草稿只表达原型反馈，不代表真实持久化。
- 提交普通审批后，申请进入采购申请详情所表达的后续查看状态。
- 提交大额审批后，申请进入审批处理。
- 审批人提交审批结果后，系统应表达该申请已有审批意见。
- 审批步骤包括申请人提交、直属审批和采购处理。
- 审批时间线用于表达提交申请、部门负责人审批和采购专员处理的先后顺序、处理时间和状态。
- 审批工作流用于表达草稿、提交、部门审批、财务审批、采购执行、完成和驳回之间的业务流转。
- 申请状态看板用于表达草稿、审批中、待采购和已完成申请的统计分组。
- 创建向导用于表达基础信息、采购明细、附件确认和提交审批的顺序。
- 交付日历和甘特排期用于表达合同确认、备货、物流和验收的计划口径。
- 附件抽屉用于表达查看和补充合同、报价单或预算材料的业务需求，不定义上传实现。
- 驳回确认后应表达已有驳回意见，便于申请人理解后续修改原因。

## 例外与备注

- 采购申请列表默认关注最近 90 天申请。
- 采购明细用于研发理解一条申请中可能包含多个采购项。
- 审批步骤只表达业务状态，不模拟真实审批流。
- 审计日志只表达业务留痕要求，不定义日志存储。
- 关联单据关系图只表达业务关系，不表示数据库关系或接口依赖。
- 树形品类结构只表达分类和选择口径，不表示数据库分类模型。
- 供应商与品类参考页只做参考展示，不提供供应商维护能力。
