# 采购申请管理系统 前端需求说明

## 文档边界

本文档基于 `spec-bifrost.json` 导出，面向前端和产品验收沟通。内容只描述用户可见页面、字段、交互、提示和业务备注，不要包含接口定义、数据库设计、技术架构、代码结构或任务拆分。

用户原始场景中的“申请单列表”“创建申请”“审批详情”分别对应本示例中的采购申请列表、新建采购申请和采购申请详情。

## 页面清单

| 页面 | 路由 | 导航 | 用途 |
| --- | --- | --- | --- |
| 采购申请列表（申请单列表） | `/purchases` | 采购管理 / 采购申请 | 查看、筛选采购申请，并进入详情或新建申请。 |
| 新建采购申请 | `/purchases/new` | 采购管理 / 新建申请 | 填写采购申请信息并提交审批。 |
| 采购申请详情 | `/purchases/detail` | 不在主导航展示 | 查看申请信息、明细和审批进度。 |
| 审批处理 | `/approvals` | 审批 / 审批处理 | 审批人查看待处理申请并填写审批意见。 |
| 供应商与品类参考 | `/suppliers` | 基础信息 / 供应商参考 | 查看采购品类和供应商选择口径。 |

## 页面流程

- 用户从采购申请列表进入新建采购申请，填写基本信息后可保存草稿、提交普通审批或提交大额审批。
- 申请金额小于等于 50000 时，提交普通审批后进入采购申请详情。
- 申请金额大于 50000 时，提交大额审批后进入审批处理。
- 用户可从采购申请列表查看采购申请详情。
- 用户可在采购申请列表对勾选申请执行批量导出，前端只表达批量动作入口和反馈。
- 审批处理页提交审批结果后表达审批动作完成，不模拟真实后端流转。
- 审批人选择驳回时，需要通过驳回确认弹窗确认原因。

## 页面级说明

### 采购申请列表

- 待处理概览展示审批中、大额申请和待补附件三个指标，用于让审批人和采购专员快速理解列表状态。
- 筛选条件包含审批状态和采购类型；审批状态口径以审批流程当前节点为准。
- 申请列表展示申请编号、申请标题、申请金额和审批状态。
- 列表默认展示最近 90 天申请。

### 新建采购申请

- 基本信息表单包含申请标题、采购类型、申请人、申请部门、申请金额、采购明细数量、期望到货日期、供应商等级、附件、预算说明和资产用途。
- 申请人默认值为当前用户。
- 供应商等级需要先选择采购类型后再确认。

### 采购申请详情

- 申请摘要展示申请编号和审批状态。
- 详情分组包含基础信息、采购明细、审批记录和附件，帮助不同角色快速定位关注内容。
- 采购明细表展示物品名称、品类标签、数量和单价。
- 附件查看抽屉展示合同或报价单附件，用于表达查看和补充材料的需求，不上传真实文件。
- 审批步骤展示申请人提交、直属审批和采购处理；暂无审批记录时显示空状态。
- 审批时间线展示提交申请、部门负责人审批和采购专员处理，并带处理时间和状态说明。

### 审批处理

- 审批意见表单包含审批结论和驳回原因。
- 审批结论支持通过和驳回。
- 驳回确认弹窗要求审批人再次填写确认驳回原因，确认后显示“已记录驳回意见”。

### 供应商与品类参考

- 供应商卡片展示优选供应商、合格供应商和临时供应商。
- 采购品类层级以树形结构展示办公用品、软件服务和固定资产及其子分类。
- 本页只做参考展示，不提供供应商维护能力。

## 字段与交互规则

以下为字段级说明和交互规则汇总。

- 申请标题、采购类型、申请人、申请部门、申请金额和采购明细数量为必填字段。
- 申请金额必须大于 0。
- 采购明细数量至少为 1。
- 期望到货日期不能早于提交日期。
- 附件在软件服务采购时必填；固定资产采购且金额超过 10000 时也必填。
- 预算说明在申请金额超过 50000 时必填。
- 资产用途仅在采购类型为固定资产时展示。
- 驳回原因仅在审批结论为驳回时必填。

## 操作反馈

- 新建申请：从采购申请列表跳转到新建采购申请。
- 查看详情：从采购申请列表跳转到采购申请详情。
- 批量导出：对勾选申请显示“已生成选中申请的导出任务”，批量操作作用于勾选的申请，不是单行操作。
- 保存草稿：显示“草稿已保存到本地原型状态”，MVP 只表达交互反馈，不持久化真实数据。
- 提交普通审批：申请金额小于等于 50000 时可用，显示“已提交普通审批”，并进入采购申请详情。
- 提交大额审批：申请金额大于 50000 时可用，显示“已进入大额审批路径”，并进入审批处理。
- 提交审批结果：表达审批人提交审批意见，不定义后续技术处理。
- 关闭抽屉和取消弹窗只表达原型层面的关闭行为。
- 确认驳回：显示“已记录驳回意见”。
